The Request Panel is where you build requests. It is split between the **URL & method bar**, the **request editors** (parameters, headers, body), and the **Response Panel**.

## URL & method

Enter a full URL in the URL bar: `https://api.example.com/users`.

Supported HTTP methods:

- `GET` — retrieve data
- `POST` — create data
- `PUT` — update data
- `PATCH` — partially update data
- `DELETE` — delete data

When you type `{{...}}` placeholders in the URL, Reqly automatically detects them and lists matching [variables](/docs/environments) below the input bar.

## Headers

Add custom headers using the key-value editor. Common headers such as `Content-Type` and `Authorization` are prefilled for convenience.

<Callout>
  Headers can use `{{environment variables}}` — the values are resolved at request time from the currently active environment.
</Callout>

## Query parameters

Use the **Params** tab to add query string parameters as key-value pairs instead of hand-editing the URL. Reqly keeps the URL and the parameter list in sync.

## Request body

The **Body** tab supports several content types:

- **JSON** — a syntax-highlighted editor with validation
- **Form data** — key-value pairs in `multipart/form-data`
- **Form URL-encoded** — standard `application/x-www-form-urlencoded`
- **Raw** — plain text, HTML, XML, or custom content types
- **Binary** — file upload

| Type | Content-Type header | Editor |
| --- | --- | --- |
| JSON | `application/json` | JSON with validation |
| Form data | `multipart/form-data` | Key-value |
| URL-encoded | `application/x-www-form-urlencoded` | Key-value |
| Raw | custom / auto | Plain text |
| Binary | `application/octet-stream` | File picker |

## Environment variables

Variables can be referenced anywhere in the request — **URL**, **headers**, and **body** — using the `{{VARIABLE_NAME}}` syntax. They are resolved at send time from the active environment. See [Environments](/docs/environments).

## Response viewer

After sending a request, the Response Panel shows:

- **Status code** with a color indicator — `2xx` green, `4xx` amber, `5xx` red
- **Response time** and **size**
- **Headers** — the response headers table
- **Body** — with syntax highlighting and JSON formatting
- **Cookies** — cookies received from the server

Click any status range (2xx / 4xx / 5xx) chip to jump to relevant details.

## Replay & follow-up

Every request you send is saved. From [Request history](/docs/history) you can:

- **Replay** — reopen the exact request in the editor
- **AI Follow-up** — generate a related request using AI (see [AI](/docs/ai))
