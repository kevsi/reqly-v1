Tous les outils sont des invocations JSON-RPC `tools/call` avec un `inputSchema` JSON-Schema (comme servi par `tools/list`). Les résultats sont retournés comme texte JSON formaté. Les outils qui ne peuvent pas satisfaire un appel retournent `isError: true` avec un message lisible au lieu de lever une exception.

Les outils sont groupés ici pour la lisibilité :

## Conventions

**IDs.** Les collections, requêtes, dossiers et environnements sont identifiés par des IDs stables (`col-…`, `req-…`, `env-…`, `fld-…`). Les outils d'exécution acceptent aussi le **nom unique** d'une requête comme `request_id`, pour que les agents puissent utiliser des références lisibles. Obtenez les IDs depuis `list_collections`, `list_requests`, `get_collection_tree` ou les ressources MCP.

**`env_name` optionnel.** Les outils d'exécution acceptent un `env_name` ; quand omis, ils utilisent le défaut `--env` du serveur, puis les variables du bundle.

**Erreurs.** Une recherche échouée retourne quelque chose comme `Collection not found: col-xyz` avec `isError: true`, pour que les agents puissent récupérer gracieusement.

**Timeouts.** Les outils d'exécution acceptent `timeout_ms` ; le défaut du serveur est 30 s.
